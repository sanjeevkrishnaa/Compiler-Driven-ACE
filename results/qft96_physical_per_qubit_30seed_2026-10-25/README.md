# QFT-96 physical-timing per-qubit rerun

This is an independent 30-seed rerun on branch
`codex/ace-scheduler-correctness`. It uses the QFT-96 trace from
`qft96_corrected_scheduler_2026-10-25`, 4×4 mesh, four shared memories per
core, three compiler memories per core, generation capacity three, event-driven
per-qubit admission, and `pregeneration-buffer-ms=0`. The simulator uses the
pinned ACE SeQUeNCe 0.8.1 environment.

Command shape:

```text
python -m run_trace_comparison --strategies on-demand,dynamic \
  --seeds 0,...,29 --total-memories 4 --compiler-memories 3 \
  --generation-capacity 3 --scheduler per-qubit --admission event \
  --pregeneration-buffer-ms 0 --stop-after-workload
```

All 60 runs completed every 4,954 request (`completion_rate=1.0`). Values are
mean ± sample standard deviation over the 30 physics seeds:

| Policy | Fair request latency | Makespan | Admission wait | Generation/service | Delivered fidelity |
| --- | ---: | ---: | ---: | ---: | ---: |
| ODG / on-demand | 1.52563 ± 0.01597 ms | 4.33718 ± 0.02584 s | 0.20024 ± 0.01178 ms | 1.12539 ± 0.01206 ms | 0.949813 ± 0.000000 |
| Dynamic | 2.57005 ± 0.09601 ms | 4.69385 ± 0.08558 s | 1.63767 ± 0.08285 ms | 0.73194 ± 0.01765 ms | 0.943033 ± 0.000230 |

`summary.csv` contains one row per policy and seed; `metadata.json` records the
trace, source hashes, simulator parameters, and metric version. The result
matches the earlier headline row (`1.526 ms` ODG and `2.570 ms` Dynamic) after
rounding.

## Figures

The figures are generated by `tools/plot_qft96_comparison.py` directly from
`summary.csv`:

- `figures/latency-makespan.png` compares fair request latency and whole-trace
  makespan with sample-standard-deviation error bars.
- `figures/latency-decomposition.png` separates admission wait, RSVP/control
  guard, and generation/service time.
- `figures/latency-distribution.png` shows the per-seed latency distributions.
