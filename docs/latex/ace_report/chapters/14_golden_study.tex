\chapter{Fresh Golden Study: Contract and Execution Record}

This chapter is the living record for the consolidated experiment program. It is
kept separate from historical ACE results so that a result cannot be promoted merely
because it exists in an older output directory. Every accepted observation must have
an immutable trace hash, a configuration manifest, paired seeds, complete requests,
and a source CSV listed in the study registry.

The cross-policy headline metric is request eligibility-to-EPR-delivery latency. It
includes admission wait, reservation, retry, and generation time. It excludes time
before eligibility during which a cached pair was merely stored. Whole-program cost
is reported separately as makespan.

The planned capacity study includes constrained settings and deliberately labelled
architecture-scaling settings. Capacities greater than the current four-memory model
are sensitivity points, not claims about the baseline hardware. The torus arm uses
Dijkstra routing only. Mesh routing comparisons hold a placement contract fixed.

The ten workload inputs are frozen QASM files recovered with SHA-256 provenance
from the historical MQT study archive. They are input evidence, not recycled
observations: fresh T-HQA placements (and the HQA control placements) are generated
from this corpus into immutable placement contracts before route expansion. The
mapping tool has no implicit workload, seed, topology, or routing default. It refuses
execution when the declared QASM parser is absent rather than selecting another
parser. At the time the contract scaffold was created, that parser dependency was
absent, so no mapping result was recorded until the fresh mapper stage could run.

The parser was subsequently installed in the project environment and the fresh
mapping stage completed. The mapping audit validated all 300 derived route
artifacts (placement hash, input hash, endpoints, adjacency, migration count and
hop count). Table~\ref{tab:golden-mapping-control} is the mesh--XY mapper-only
control; its exact machine-readable source is named in the caption. It does not
imply an ACE latency result.

Across the ten frozen inputs, T-HQA produces 16,758 mesh--XY hops compared with
HQA's 19,079, while producing 7,702 versus 7,587 logical migrations. This is a
trade-off to evaluate with ACE, not a declaration of universal superiority.
Crucially, the three mapper/reliability seeds yielded one unique placement for each
workload/algorithm/topology; they must be treated as reliability-route checks, not
independent placement replications.

At report build time, this chapter contains no performance conclusion until the
contract has been made run-ready and the corresponding registry rows, raw CSV files,
and validation records exist.
